# Результаты AIM2

Прочитай [подключение](../aim2-api/SKILL.md). Различай SERPset с разобранной выдачей,
сырые HTML-артефакты, успешность сбора и готовность оценок/метрик.

## Найти выходы

- Если дан experiment_id: прочитай историю `/experiments/{id}/instances` и выбери
  нужный запуск по задаче/времени; не считай latest нужным без проверки.
- Если дан instance_id: `GET /experiment-instances/{id}`.
- Если дан cron_id/run_id: `GET /crons/{id}/runs/{run_id}` и его instance.
- Для поиска готового набора используй `/serpsets/catalog?limit=100&offset=0`,
  затем подробный GET по ID при необходимости.

Бери каждый `subexperiments[].serpset_id`, учитывай `serpset_ids` и legacy
`serpset_id`, удаляя только повторы ID выходов. Сохраняй соответствие хост →
SERPset. Некоторые хосты готовы раньше других; при запросе промежуточной выгрузки
скачай доступные и явно укажи незавершённые. Не представляй такой экспорт полным.

Проверь counters/status, postprocess_status/error и result_lifecycle_state:
failed может иметь полезный частичный выход; completed сбор ещё не гарантирует
готовых метрик. expired/deleting или удалённый результат не восстановится от
повторного GET. Не перезапускай сбор без поручения пользователя.

## Скачать JSON

```sh
python3 <skills-dir>/aim2-api/scripts/aim2_api.py GET '/serpsets/123/export?full=true' --output serpset-123-full.json
python3 <skills-dir>/aim2-api/scripts/aim2_api.py GET /serpsets/123/export --output serpset-123.json
```

По умолчанию экспорт — массив SERP; `full=true` возвращает объект с метаданными
и массивом `content`. Для отдельной строки есть
`GET /serpsets/{id}/serps/{index}/export`, index начинается с нуля, ответ — массив
с одним SERP. `compare-snapshot` — сокращённое представление для UI, его не следует
выдавать за полный экспорт. Большой JSON загружай потоково в файл; клиент не
печатает его с `--output`. Проверь JSON и количество SERP; для больших файлов
используй потоковый парсер, а не загрузку целиком в память.

Для воспроизводимости сохрани рядом небольшой manifest: выбранные experiment/
instance или cron/run IDs, замороженную basket_revision_id из `/config`, хосты,
SERPset IDs, время выгрузки, счётчики успешных/ошибочных строк, postprocess_status,
имена файлов и их SHA-256. Метрики могут измениться позднее, поэтому фиксируй
время выгрузки. В отчёте давай локальные пути и полноту результата.

## Органические ссылки

В каждом SERP сохраняй query, status и порядок components; органические URL
находятся в `components[].info.url`, ранги — в `components[].info.rank`.
Сохраняй дубли и пустые успешные выдачи, не заменяй пропуски выдуманными URL.
При CSV-выгрузке полезны поля: host, serpset_id, query_index, query_text, region,
device, status, rank, url. Не объединяй строки разных регионов/устройств только
по тексту запроса. Отсутствующие данные оставляй пустыми, а не угадывай.

## HTML

Экспорт SERPset не содержит сами HTML-файлы. У захватов ищи `capture.artifact`
(для full-экспорта внутри content), где есть url, bytes, sha256 и иногда
query_redacted. `serp_url` — исходная поисковая страница, а не сохранённый HTML.

Скачивай только предоставленный артефакт по выбранному доверенному origin,
отдельным HTTP-клиентом **без Bearer AIM2**. Не передавай токен сервиса в S3.
Не следуй редиректам автоматически; проверь HTTP-успех, длину и SHA-256 до
окончательного сохранения. Для отсутствующего bytes/hash честно укажи предел
проверки. Делай уникальные имена по хосту и индексу запроса; отдельно фиксируй
неудачи, не теряя остальные файлы.

Публичная ссылка может иметь удалённые query-параметры (`query_redacted:true`),
поэтому приватный/истёкший объект может вернуть 403. Не пытайся восстановить
подпись или читать внутреннюю очередь: нужен авторизованный источник ссылки
или доступ к хранилищу. Не повторяй поиск для получения «того же» HTML.
Не печатай подписанные URL; храни такие ссылки только в приватных артефактах.
