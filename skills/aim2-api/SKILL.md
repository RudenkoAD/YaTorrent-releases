# Работа с AIM2

Выполняй задачу пользователя через API обычной учётной записи. Не нужны SSH,
исходники AIM2, прямой доступ к БД или брокеру. GUS/YaTorrent исполняет задания;
AIM2 хранит корзины, определения, историю запусков и SERPset.

## Подключение

Используй предоставленные пользователем адрес установки и существующий токен.
API base у веб-установки обычно `https://<installation>/api`; для прямого backend
адрес может быть без `/api`. Не угадывай домен или окружение. Если адрес или
авторизация отсутствуют, запроси их; токен предложи сохранить локально в файл
с доступом только владельцу. Пользователь может скопировать свой API key
из аккаунта AIM2 (имя пользователя → Account). Не проси присылать секрет в чат.

Настройки клиента, Python 3.10+ и только стандартная библиотека:

```sh
export AIM2_API_BASE='https://<installation>/api'
export AIM2_TOKEN_FILE='/absolute/path/to/private-token.txt'
python3 <skills-dir>/aim2-api/scripts/aim2_api.py GET /auth/me
```

Заменяй `<skills-dir>` реальным каталогом установленных скиллов. Токен читается
из файла в процессе, передаётся в Bearer-заголовке и не включается в URL.
Клиент требует HTTPS; `--allow-http` используй только для явно выбранной
пользователем доверенной HTTP-установки. TLS-проверку не отключай.
Редиректы не выполняются. Не выводи содержимое файла токена или auth-ответы
с ключом в чат, логи, репозиторий или результаты.

Все скиллы пакета устанавливаются вместе. Выбирай по намерению пользователя:

| Намерение | Скилл |
| --- | --- |
| Список запросов, импорт, изменение корзины | [aim2-api-baskets](../aim2-api-baskets/SKILL.md) |
| Сравнить варианты, создать или запустить эксперимент | [aim2-api-experiments](../aim2-api-experiments/SKILL.md) |
| Регулярный сбор, расписание, ручной запуск крона | [aim2-api-crons](../aim2-api-crons/SKILL.md) |
| Проверить запуск, скачать SERPset, URL или HTML | [aim2-api-results](../aim2-api-results/SKILL.md) |

## Как выполнять запросы

```sh
python3 <skills-dir>/aim2-api/scripts/aim2_api.py GET '/baskets/catalog?limit=100&offset=0'
python3 <skills-dir>/aim2-api/scripts/aim2_api.py POST /baskets --json-file basket.json --output created-basket.json
python3 <skills-dir>/aim2-api/scripts/aim2_api.py GET /serpsets/123/export --output serpset-123.json
```

`--json-file` передаёт UTF-8 JSON; `--output` потоково сохраняет ответ через
временный файл, затем переименовывает его. Существующие файлы не заменяет.
Без `--output` ответ идёт в stdout: используй это только для небольших безопасных
ответов. Файлы с данными пользователя храни вне публичного репозитория.

Списки возвращаются массивами: проходи `limit`/`offset` до короткой страницы.
Не полагайся на первый результат поиска или уникальность имени; используй ID.
Неизвестный путь или поле сверяй с OpenAPI выбранной установки, если он доступен
(обычно `/openapi.json` относительно API base). Контракты здесь проверены по
исходникам AIM2 2026-10-16; это не подтверждение версии или состояния сервера.

Клиент не повторяет запросы автоматически. При 401/403 проверь учётную запись,
при 404 — окружение, путь и ID. При 409 перечитай объект и разберись с конфликтом;
при 422 исправь вход по схеме. Сетевой сбой/5xx после записи означает неизвестный
исход: сначала проверь readback; для идемпотентных ручек повторяй прежний ключ.
Клиент сообщает HTTP-код без тела ошибки, чтобы не раскрывать входные данные;
при необходимости исследуй безопасно отредактированные детали отдельно.

## Естественный рабочий процесс

Извлеки параметры из запроса и существующих объектов; уточняй только значимые
пробелы: окружение, хост/вариант, регион/устройство, время или объём запуска.
Для запроса «создай корзину и запусти сравнение» выполни всю цепочку в пределах
поручения. Для «подготовь эксперимент» сохрани определение и предъяви его ID;
запуск — отдельное действие. Создание активного крона разрешает будущие запуски,
поэтому при неясном намерении подготовь `enabled:false` и уточни активацию.
Не вставляй повторные подтверждения перед уже порученными действиями.

После записи прочитай объект по ID и проверь существенные поля. При потерянном
ответе не создавай дубликат наугад. Не включай runtime, не меняй deployment и не
потребляй брокер для проверки API. Перед реальным запуском прочитай
`GET /experiments-runtime`: disabled/mock/broker — разные режимы; mock не даёт
реальных SERP. Отчёт содержит IDs, ревизии, выполненные действия, состояние и
ссылки/пути результатов, но не секреты и подписанные URL.
